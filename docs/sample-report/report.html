Methodology

  • Engine: axe-core 4.14.0 with the tags wcag2a, wcag2aa, wcag21a, wcag21aa, wcag22a, wcag22aa, plus three keyboard checks run in a real Chromium.
  • Deterministic: the audit, the source mapping, the edits, the bounds check, the acceptance gate (fingerprints before and after), the combine and every output file.
  • LLM: the fake provider (10 call(s), prompt v1) proposes a value only (alternative text or a control name). It never writes a diff, runs a gate or decides. Every such value is marked for human review.
  • Heuristic: the keyboard checks. A trap or an obscured focus is reported as needs review, not as a failure.
  • Persona severities are a project rating from 0 to 3 taken from a fixed catalog, not a measurement. Each card links the WCAG 2.2 Understanding page that names who benefits.
  • Contrast fixes change the HSL lightness of one colour in an inline style until the ratio is met. They keep hue and saturation but do not know the design, so they are always marked for design review.
  • Verified means: re-audited in a real browser; the target failure is gone and no new axe or keyboard finding (violation or needs-review) appeared. It does not see layout, script errors or meaning; LLM-written text is marked for human review.
